## 目标与现状

产出能与研发讨论且与指定版本一致的数据流、Prompt 和参数说明，解释为何选择混合检索、受约束编排与降级。当前已有 pgvector 向量检索、PostgreSQL 全文及关键词匹配、RRF 融合、可选 Rerank 与引用原文；尚未证明混合方案的实际收益。

RRF 是“倒数排名融合”。当前关键词路径使用 PostgreSQL 全文排序及字面匹配，不应严格称为标准 BM25。XML、Few-Shot、`temperature=0.05` 或特定 Top-P 的使用与效果均需核对，不能直接套用示例。

### 代码级端到端数据流

```mermaid
flowchart TD
  U[浏览器输入] --> W[Next.js /api 代理<br/>Cookie 转 Bearer] --> A[FastAPI POST /runs<br/>保存 Run 与会话] --> R{AGENT_MODE}
  R -->|echo| E[回显演示<br/>不检索、不代表真实推理]
  R -->|graph| C[意图分类]
  C -->|低置信度| END1[澄清后结束]
  C -->|可执行| P[策略计划<br/>默认 static_plan]
  P --> D[依赖调度 dispatch]
  D --> Q[按需检索/只读工具]
  Q --> H[证据审查 review]
  H -->|需补证且 retry 开启| D
  H -->|回答或停止| G[上下文组装与生成]
  Q -. 检索 .-> V[pgvector 向量候选]
  Q -. 检索 .-> K[PostgreSQL FTS + 字面词项候选]
  V --> F[RRF 融合 Top-K]
  K --> F
  F --> RR{Rerank 开启且可用?}
  RR -->|是| RC[重排]
  RR -->|否/失败| X[保留融合排序]
  RC --> G
  X --> G
  G --> S[SSE token/done 与引用]
  S --> UI[前端更新回答/时间线/引用]
  S --> DB[Run 结果字段持久化]
  G --> TD[若建单意图：结构化待确认草稿<br/>保存来源 Run 与 fingerprint]
  TD --> CONF[后续明确确认创建]
  CONF --> VALID[程序核验最新有效草稿/拒绝状态/指纹]
  VALID -->|有效| WRITE[create_ticket 写入并回传结果]
  VALID -->|无效| BLOCK[失败关闭，不写入]
  WRITE --> DB
  D --> HITL[其他高风险工具：interrupt 等待批准]
  HITL --> RES[POST /runs/{id}/resume]
  RES --> HITLWRITE[恢复后执行对应的已批准工具]
```

该图描述代码路径，不表示每个分支在本批都执行；本批没有启用动态计划、重试或 Rerank。

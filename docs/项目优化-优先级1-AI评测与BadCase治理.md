# 优先级 1：AI 评测与 Bad Case 治理

[返回项目优化总览](项目优化总览.md)

## 目标与现状

建立可复查的质量基线，定位失败并完成至少一轮同条件对照，展示准确性、安全性、延迟和成本之间的取舍。当前已有黄金集、规则评测、Trace 和报告机制；规则裁判不等于人工或 LLM 语义评审，历史离线数据不代表当前真实模型效果。

现有工具指标主要衡量期望工具是否出现，不完整检查参数、额外调用或执行成功；引用存在也不证明回答受到证据支持。Recall@5 尚未建立稳定标注；逐调用 Token usage 已有线上验收，整 Run 成本、浏览器端 TTFT 和幻觉率仍需补齐。

## 数据与指标口径

| 指标 | 计算或记录方式 | 注意事项 |
| --- | --- | --- |
| 问题级幻觉率 | 存在至少一条无依据或与材料矛盾的关键事实断言的回答数 ÷ 可评审回答数 | 人工对照指定材料；无法判断单列。无资料时正确说明不足不算幻觉 |
| 引用支持率 | 被抽查事实断言中，引用片段足以支持断言的数量 ÷ 可评审事实断言数 | 引用可打开与语义支持分开统计，保留断言级标注 |
| 工具调用准确率 | 应调用样本中，工具选择及关键参数均正确的样本数 ÷ 可评审应调用样本数 | 另报告不应调用样本误调用率、执行成功率及额外调用；禁止工具单独判失败 |
| 任务验收率 | 满足该场景全部预定验收标准的有效样本数 ÷ 有效评审样本数 | 汇报分场景结果、失败与跳过；缺证据不能直接算通过 |
| Recall@K | 有相关资料的查询中，前 K 个结果包含至少一个已标注相关片段的查询数 ÷ 此类查询数 | 先冻结文档切片和相关性标注；空库和无相关资料单列 |
| TTFT | 浏览器提交请求至收到首个有效回答文本的时间 | 分别记录服务端生成首字时间；说明是否包含网络、排队和检索；状态提示不算回答首字 |
| 延迟与成本 | 系统处理及任务总耗时 P50/P95；模型实际 usage 与对应价格计算每任务费用 | 单列人工等待；注明模型、价格和缺失率；小样本尾分位不作生产承诺 |
